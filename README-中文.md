# PTFree 2.0.6

新部署时，登录后进入「系统 → 全局配置 → 功能模块管理」启用所需模块，然后用侧栏「PT配置」旁的「＋」或该页的「＋ 添加站点」，选择 M-Team 并保存站点 API Access Token。左上角 PTFree 图标返回总运行概览。

从 MTFree 1.3.9 升级时，请先停止旧服务并备份整个数据目录。在新程序中继续使用原数据目录，并用新目录中的脚本安装或启动服务。初始密码、凭据、历史和统计随原目录保留。


M-Team 免费种子自动发现与下载服务，提供中文网页管理界面，支持 Windows 和 Linux。

## Windows 安装

可以把 PTFree 部署在 **192.168.1.20** 上，并使用这台机器的本地目录保存种子文件。

1. 解压整个 Windows 压缩包，例如解压到 `C:\ai\PTFree`。升级时先在新包内运行 `0-Stop_Service.bat` 停止旧实例。
2. 双击 `1-Install_Service.bat`。Windows x64 发行包包含 Python 3.14.10 和所需依赖，不需要另装 Python，也不会改动你的 ComfyUI Python。
3. 安装脚本会打开数据目录。在其中找到 `初始管理密码.txt`，复制里面的随机管理密码。
4. 需要自启时运行 `2-Enable_AutoStartSystemService.bat`，再双击 `3-Start_Service.bat`，服务在后台监听 `0.0.0.0:8787`。检测到网页就绪后会打开浏览器，启动窗口会自动关闭。
5. 使用初始密码登录。可以在「全局配置」底部修改管理密码。
6. 在「系统 → 使用帮助」选择 Freeseed 或 流量助手，按照对应步骤配置并测试。

安装脚本的命令输出使用英文，网页和本文使用中文。

## 获取认证信息

在你自己的浏览器登录 M-Team，进入 **控制台 → 实验室 → 存取令牌**，创建 API Access Token，复制到网页「PT配置 → M-Team」。

不再需要 `did`、`visitorid` 或网页 Cookie。官方要求第三方使用 API 令牌，并将 `/login`、`/apikey/**` 列为第三方禁止调用的路径，因此程序不自动登录、不自动创建令牌，也不读取浏览器凭据。令牌通常不需要每轮更新；失效、撤销或权限变化时需手动替换。请不要把令牌发到聊天中。

API 地址默认 `https://api.m-team.cc/api`，也支持 `https://api.m-team.io/api`。程序不会自动来回切换域名重试，以免请求数量失控。

参考官方说明：https://wiki.m-team.cc/zh-tw/api

## 保存种子文件

1. 在「服务配置」填写「种子文件保存目录」，例如 `D:\PT-Seeds`，并保存配置。
2. 点击「测试认证」和「测试读写」，再用「预览本页结果」检查筛选条件。
3. 取消「仅预览」，保存后点击「启动服务」。

文件会以 `MT-种子ID.torrent` 保存。程序先写入 `.part`，完成后再重命名；中途停止时，可从保存记录恢复。使用 Windows 共享目录可填写 UNC 路径。使用 Linux 时，填写本机目录或已挂载的共享路径。

从旧版升级会保留原种子目录、站点令牌和下载历史。旧版未设置种子保存目录时，升级后先填写目录，再开启扫描。

白名单、黑名单每行一个普通关键词，忽略大小写。白名单任意命中即可，黑名单任意命中就排除；不用正则表达式。

支持标准免费、双倍上传免费，以及 `mallSingleFree` 中处于有效窗口的活动免费。不会仅因种子置顶而认定它免费。下载前会重新请求详情并检查规则。站点字段变化、缺失或返回错误页面时，该条操作失败并记录原因。

开启真实扫描后，列表中已发布且符合规则的种子也会进入队列。限时免费活动中的老种按免费截止时间复核，并继续应用免费剩余时间、其他筛选条件和站点历史去重。

## 网络与请求频率

PTFree 直接使用 M-Team API 返回的 HTTP 或 HTTPS 下载链接，最多跟随 3 次跳转。相对链接按当前请求地址解析。下载请求没有域名白名单，API 令牌仅用于认证 API 请求，HTTPS 请求照常校验证书。升级后，旧版域名、协议或端口拦截造成的失败会重新排队，并按现有筛选和站点历史去重规则处理。

正式扫描在申请种子下载链接前，使用当前 API 令牌批量查询 M-Team 下载历史。正在下载、做种或已有历史的种子会记为「站点已有记录」，此后自动跳过。更换 API 令牌时，站点历史会按新令牌重新核对。预览也显示站点跳过原因。

如果历史接口超时、限流、拒绝访问或返回不完整数据，本轮暂缓申请种子，原因显示在运行日志里。仅保存过 `.torrent` 或刚添加任务且尚未向 Tracker 汇报时，站点可能还没有记录。

IPv4 优先只影响 PTFree 的站点请求。IPv4 优先按 IPv4 地址在前的顺序尝试，失败后允许 IPv6；仅 IPv4 模式完全不尝试 IPv6。TLS 验证始终开启。

本版本为直连 HTTP 客户端，不自动读取系统代理或 OpenClash 环境变量。如果你的网络必须通过代理访问站点，应先使用系统透明代理等方式让应用能直连访问，或后续增加显式代理配置。

程序记录站点请求次数。默认关闭本地请求配额，可在「服务配置」中启用。启用后的程序上限如下：

| 操作 | 程序上限 |
| --- | --- |
| 列表查询 | 滚动 24 小时最多 900 次 |
| 站点历史查询 | 滚动 1 小时最多 60 次，24 小时最多 900 次 |
| 详情查询 | 滚动 1 小时最多 80 次 |
| 下载令牌获取 | 滚动 1 小时 80 次、24 小时 800 次 |
| 种子文件获取 | 滚动 1 小时 80 次、24 小时 800 次 |
| 用户信息测试 | 滚动 1 小时最多 30 次 |

种子任务从查详情开始计时，两条任务的启动至少间隔 3 秒。启用本地配额时，达到上限后按滚动窗口恢复，并在下载历史里显示「等待配额」。HTTP 429 会遵循有效的 `Retry-After`，缺省等待 15 分钟。连续 3 条种子遇到同一接口错误后暂停 60 秒，恢复时先试一条。管理页横幅显示冷却来源、剩余时间和预计恢复时间。日志记录接口阶段、HTTP 状态和可安全显示的业务码。认证失败会暂停自动请求，更新令牌或认证测试成功后恢复。

## 故障恢复

采用三层处理：

1. **网络层：** 连接与读取超时，响应大小限制，安全错误信息，不把令牌、下载链接或响应正文写入日志。
2. **操作层** 扫描、认证测试、目录测试等分别运行在子进程。测试操作总上限 60 秒，扫描总上限 900 秒。DNS、SMB 或读取卡住超过上限时结束该进程。持久化历史保留，后续轮次继续处理。
3. **服务层：** 独立看门狗检查网页进程心跳；超过 45 秒停止更新时重启。Windows 使用 Job Object 管理子进程生命周期，Linux 使用进程组。看门狗本身由操作系统自启任务或 systemd 负责恢复。

网络错误会逐步增加等待时间，最长到一小时。单种失败达到最大尝试次数后停止自动重试；在下载历史点击「重试」恢复。没有实现无限快速重试。

「暂停服务」终止当前扫描并取消排队的扫描任务。已启动的连接测试等只读操作可以继续完成。修改配置时如果仍有操作进程，需等待结束，或先暂停扫描。

网页右上角的「停止服务」退出 PTFree，包括网页进程、当前操作和看门狗。之后用原来的启动脚本、Windows 计划任务或 systemd 启动。Windows 后台计划任务在下次登录时仍会按设定运行。Linux 已注册旧版 systemd 服务的用户，升级后需重新执行 `install-service-linux.sh`，沿用原来的监听地址和端口参数。新版 systemd 单元只在异常退出时重启。

## Windows 自启与局域网访问

双击 `2-Enable_AutoStartSystemService.bat`，注册当前用户登录时在后台启动。任务直接使用 `pythonw.exe` 运行，启动和扫描时无需控制台窗口。进程意外退出后，任务计划程序会重启它。需要立即启动时，在 PowerShell 里运行 `Start-ScheduledTask -TaskName 'MTFree-AutoDownload'`。

从旧 Windows 包升级时，用同一个 Windows 账户双击 `0-Stop_Service.bat` 停止 PTFree。该脚本可直接从解压后的新包执行，即使网页访问失败也可停止旧进程。然后运行 `1-Install_Service.bat`。已设置登录自启的用户，从新目录重新执行 `2-Enable_AutoStartSystemService.bat` 更新任务。之前启用了 `-Port` 或 `-AtBoot` 的用户，继续使用原来的参数。需要查看前台输出时运行 `3-Start_Service.bat -Foreground -NoBrowser`。

如果希望无需登录就开机启动，在 **管理员 PowerShell** 中进入程序目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-autostart-windows.ps1 -AtBoot
```

按系统提示输入运行此程序的同一个 Windows 账户的实际密码（不是 PIN），Windows 任务计划程序会保存此凭据。开机后 SMB 访问也需要这个账户拥有相应权限。

手动和自启入口都默认监听 `0.0.0.0:8787`。从其他电脑打开 `http://192.168.1.20:8787`（以部署主机的实际地址为准）。只允许本机访问时，启动或登记自启时传入 `-LocalOnly`。Windows 防火墙需要允许可信局域网访问该端口，启动脚本不改动防火墙。

移除自启：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-autostart-windows.ps1 -Remove
```

更换程序目录后要重新注册任务。手动窗口与自启任务不能同时运行同一数据目录；单实例锁会阻止重复实例。

## Linux 安装（Ubuntu 24.04 x86_64）

2.0.6 Linux x86_64 安装版包含源码、启动脚本及适用于 Ubuntu 24.04 / Python 3.12 的依赖 wheel，不含独立原生二进制。安装脚本使用系统 Python 创建独立环境。需要预先安装 `python3-venv`；在其他 Python 版本上可能需要联网安装匹配依赖。

将压缩包上传到目标虚拟机后解压，进入目录：

```bash
unzip PTFree-2.0.6-Linux-x86_64-Installer.zip
cd PTFree-2.0.6
bash install-linux.sh
bash run-linux.sh
```

默认只监听本机。若部署到一台局域网虚拟机（示例地址 **192.168.1.30**）并需要通过 Windows 浏览器管理：

```bash
MTFREE_HOST=0.0.0.0 bash run-linux.sh
```

浏览器访问 `http://192.168.1.30:8787`。先检查 VM 防火墙是否放行可信内网。使用其他 VM 时按其实际 IP 访问。

初始管理密码位于 `~/.local/share/mtfree/初始管理密码.txt`。显示密码只需在你自己的 SSH 终端执行：

```bash
cat ~/.local/share/mtfree/初始管理密码.txt
```

注册 systemd 用户服务并允许退出 SSH 后继续运行、开机后自动运行：

```bash
MTFREE_HOST=0.0.0.0 bash install-service-linux.sh
sudo loginctl enable-linger "$(id -un)"
systemctl --user status mtfree.service
```

关闭手动启动的实例后再注册服务。查看外层进程日志：

```bash
journalctl --user -u mtfree.service -n 100 --no-pager
```

移除服务但保留程序与数据：

```bash
bash install-service-linux.sh --remove
```

源码模式要求 Python 3.11+，先安装发行版的 `python3-venv`。`install-linux.sh` 在没有可运行二进制时创建独立虚拟环境，从 USTC PyPI 安装依赖。存在 `.venv/bin/python` 时启动脚本优先使用源码。源码核心的唯一第三方依赖是 cryptography，网页不依赖 CDN。

Linux 保存到 Windows 共享时，先挂载 SMB 共享，确认运行服务的用户能读写，再将挂载路径填入「种子文件保存目录」。

## 数据、密码与升级

| 平台 | 默认数据目录 |
| --- | --- |
| Windows 启动脚本 | `%LOCALAPPDATA%\MTFree` |
| Linux 启动脚本 | `~/.local/share/mtfree` |
| 直接使用命令行且不带 --data | `~/.mtfree` |

「PT配置」管理 M-Team API、Freeseed 扫描板块及请求选项、流量助手搜索分区与分类 ID，以及全站免费时间。全局配置页管理功能模块、qB 连接、RouterOS 连接、延迟探测、qB 整体让路及管理密码。两个模块的配置首项用于选择站点，通用筛选、目录、容量与调度在各自页面设置。取消选择并保存会暂停对应模块。配置、历史和密码都不放在程序代码目录里。Windows 安装时限制数据目录 ACL；Linux 数据目录使用 0700，敏感文件使用 0600。

API 令牌用 Fernet 认证加密，密钥为 `secret.key`。这能防止配置文件被单独拷贝后直接读到密码；**不能防止拥有同一用户文件访问权限的人读取密钥并解密**。种子文件本身可能包含个人 Tracker 凭证，不应公开分享。

升级或备份前，先完整停止进程或自启服务，再复制整个数据目录，包含密钥、配置、认证文件、数据库及其 WAL 文件。不要只备份 `settings.json`。新版沿用同一数据目录。1.2 系列的下载路径迁入原先选中的存储模式，另一种模式可以另填。

忘记管理密码时，先停止服务，再执行：

Windows 便携包：

```powershell
.\runtime\python.exe -m ptfree --data "$env:LOCALAPPDATA\MTFree" reset-password
```

Linux 二进制：

```bash
./bin/ptfree --data "$HOME/.local/share/mtfree" reset-password
```

## Prometheus 监控

`/healthz` 无需认证，只返回基础存活状态，不泄露配置。`/metrics` 支持管理会话，也支持专用只读 Bearer 令牌。后者自动保存在数据目录的 `metrics.token` 文件中，只能访问指标，不能访问配置或控制接口。

将令牌文件安全复制到 Prometheus 主机，例如 `/etc/prometheus/mtfree.token`，让 Prometheus 服务用户可读，再加入配置：

```yaml
scrape_configs:
  - job_name: mtfree
    metrics_path: /metrics
    authorization:
      type: Bearer
      credentials_file: /etc/prometheus/mtfree.token
    static_configs:
      - targets: ['192.168.1.20:8787']
```

目标地址使用 PTFree 实际部署机器。指标包括服务启用状态、最后成功检查时间、看门狗重启次数、认证异常和各状态种子数量；不要仅以 HTTP 存活判断下载是否正常。

Windows 启动脚本默认监听局域网，Linux 启动脚本默认仅监听本机。HTTP 管理和指标采集适合可信内网，公网访问应使用 VPN 或经过正确配置的 HTTPS 反向代理。当前服务对 Host 和 Origin 做校验，反向代理需保留源站 IP Host。

## 流量助手

原管理密码、令牌、历史和两组任务保存在数据目录。Windows 可以用新包的 `0-Stop_Service.bat` 停掉旧版，再用新包的 `3-Start_Service.bat` 启动。若已设登录自启，从新目录重新运行 `2-Enable_AutoStartSystemService.bat`。

### qB 连接与完成通知

在 qB 选项中开启 Web UI，填写 PTFree「全局配置」里的地址和认证方式。同机可用 `http://127.0.0.1:8091`，端口按 qB 设置填写。qB 未启用 HTTPS 时用 `http://`。可在其他电脑打开 PTFree 网页。

- **API 密钥**需要 qB 5.2 或更高版本。从 qB 的 WebUI 选项复制完整密钥，填入认证字段后可直接测试。
- **用户名和密码**用于账号登录，也适用于旧版 qB。后台最低需要 qB 4.3。使用全局未完成目录时，需要支持单任务下载路径的 qB 5.1 或以上版本。
- 「测试 qB 连接」测试表单里的当前地址与凭据。「保存连接与让路设置」后后台才会使用这些配置。密码和 API 密钥加密保存。

在「流量助手 → 调度与容量 → 托管任务状态检查」选择「定时检查」或「完成通知 + 定时检查」，可以修改任务运行时的检查间隔（15–35 秒）或点击「立即检查」。完成通知需要本机 qB，已有其他完成程序或使用远程 qB 时继续定时检查。检查只查询相关的托管哈希。远程 qB 另以 60 秒间隔读取增量卷状态。

流量助手 托管任务在 qB 中统一使用 `AutoSeeDonTouch` 标签。每轮任务仍使用独立目录，PTFree 通过本地记录、哈希、qB 添加时间和路径确认归属。升级后会清理归属明确的该模块的旧任务标签，以及 qB 中没有任务使用的该模块的旧任务标签。请先停掉旧版服务，再运行新版。完成即清理。选中「保留并转移」后，由 qB 把内容移动到设置目录下的独立子目录，随后交由 qB 管理。PTFree 发出移动命令时无需暂停任务。手工在 qB 删除的任务会在定时检查后更新状态。Freeseed 遇到重复任务时，后台只释放匹配的自有任务。

### 选种与并发

关闭「自动发现并加种」时，仍可在「种子管理」手动输入 ID，已加入的任务继续由后台管理。

- 每次向 M-Team 请求综合区和成人区中已启用的一页。每区最多 100 条，由站点按做种人数降序，PTFree 合并、去重并重新排序。分类 419 对应综合区的电影。标准免费查完后，本轮继续核对双倍上传免费的批次。
- SQLite 以种子 ID 为索引保存本轮使用记录。当前合并批次还有适合机会的候选时，程序从本地取下一个。整轮结束后新开一轮。
- 发布时间 24 小时内的免费新种、单种限时免费交给 Freeseed 按自己的规则判断。后台主要选老种，排除明确标记 HR 的种子。每次加入前复核免费，运行中按配置复核。全站免费需在「PT配置」根据站方公告填写开始和结束。活动到期时先暂停依赖该优惠的任务，并复核其实际优惠。
- 启动时先用一个下载位，按约 30 秒间隔判断是否增加一个。下载额度优先分给 qB 已放行的托管任务。已有任务在 qB 排队时暂缓提交新任务，直到队列腾出位置。容量不足时等待空间释放。疑似慢种按实际下载样本判断，清理后在历史单列。
- Freeseed 服务配置中的容量管理为可选。启用后，Freeseed 用共用的 qB Web API 直接加入专用目录。满额可以等待，或从最旧的可确认归属的任务开始回收，直到空间足够。已有文件投递模式及此前的 qB 任务不纳入回收。容量填 0 即继续使用原来的种子文件投递。

### 固态盘和内存盘

固态盘模式使用专用内容目录，流量助手存储配额与卷剩余空间分别检查。远程 qB 只提供默认卷的剩余空间，下载目录应位于默认保存目录下的直属子目录，并使用同一个卷。

内存盘模式使用实际内存保存下载内容。选择「自动创建」后，可以启动后台自动创建，或点击「保存并创建或检查」提前准备。PTFree 会选择并显示路径。只有选择「使用已有内存盘」时需要手工填写路径。qB 与 PTFree 同机，通过回环地址连接 Web API。

- Windows 自动分配空闲盘符（优先 R:）。请提前安装 ImDisk 和 AWEAlloc，以具备相应权限的账户启动 PTFree。PTFree 使用 ImDisk 的物理内存模式创建和格式化该盘，再核对驱动类型。驱动由用户安装，安装包不捆绑驱动。
- Linux 自动在 `/mnt` 下为实例创建专用目录。自动挂载需要挂载权限。qB 和 PTFree 以不同系统账号运行时，可预先挂载限额 tmpfs 并设置目录权限，再选「使用已有内存盘」。交换空间开启时必须使用支持 `noswap` 的内核与挂载。
- 内存盘内容在卸载或重启时丢失。少量种子元数据、qB 续传记录和 PTFree 数据库仍由各自应用保存。内存盘未通过核验的情况下后台暂停。

### RouterOS、让路和统计

「全局配置」内有路由地址、API-SSL、证书指纹及 PPPoE 接口（例如 `pppoe-CT`）的填写帮助。只读采样所用账号需有 `read,api` 权限。升级前已应用过 MTFree 旧版整形的用户，可以在该页点击「撤销旧版整形」移除旧规则。

「调度与容量 → 带宽调度」可选择「共享带宽」或「上传优先（自动）」。升级后沿用原来的共享带宽策略，选中上传优先并保存即可切换。

**上传优先（自动）**按 qB 全实例的实测上传保护已有种子的上传机会，只动态调整 流量助手 托管任务的下载上限。启用后先以 50 Mbps 或更低的限速建立基线，再逐步试探更高下载速率。已经观测到的上传持续下降时，降低下载速率并暂缓新增，已有任务保持连接。若上传随下载降速而回升，保持较低下载速率一段时间，稳定后逐步加回。若上传没有随之改善，恢复试探前的上限并重新观察，避免对端需求低时反复降速。每轮使用至少 90 秒的测速样本，取中位数判断。调整上限后留 15 秒让流量稳定，再开始下一轮。保护目标是已观测上传基线的 90%，实际速度取决于对端需求和线路。上传需求持续较低时，观察结束后直接使用可用下载额度。下载本来就低速，且未同时观察到上行接近饱和和延迟明显升高时，上传下降不会触发降下载试探。

参考下行扣减家庭预留下行和观测到的其他下载流量，再受托管下载总上限约束。线路繁忙时保留很低的下载速率来维持任务连接。参考上行用于判断 PPPoE 是否接近饱和，辅以可选 Ping 的延迟信号。RouterOS 暂时缺样时按 qB 数据调节。流量助手 上传优先运行期间，软件会还原自动设置的 qB 整体限速并暂停整体让路。qB 自己配置的普通和备用限速仍由 qB 执行。运行概览展示 qB 总上传、托管上传和上传目标，调度记录显示调整原因。

**共享带宽**支持从历史估算线路速率。开启历史估算时，上下行分别使用过去七天的连续五分钟平均速率峰值。缺少有效样本或峰值低于对应参考值的 65% 时，该方向用参考值。关闭历史估算后，直接使用填入的参考值。

每个方向取以下两个数的较低值作为托管总额度。

- 采用的线路速率减去家庭预留，再减去已经观测到的其他流量。
- 托管总上限。勾选「不限」时省略这项固定上限。

若采用 650 Mbps 下行和 70 Mbps 上行作为参考，家庭预留填 100 / 15 Mbps，托管总上限填 650 / 15 Mbps，其他流量接近零时，托管任务合计约可用 550 / 15 Mbps。如果其他设备已用 200 / 45 Mbps，托管任务额度降到约 350 / 10 Mbps。若额度太低，托管任务会暂停让路。已配置 RouterOS 时，缺少当前流量样本会暂停后台调度。

「全局配置 → qB 整体让路」是单独的开关，默认关闭。保存 qB 连接后，填写能稳定回应 Ping 的外网地址，再启用。首次开启时可先让 qB 空闲约半分钟以测出平时延迟。PTFree 每约 3 秒检查 qB 总速率及外网延迟。延迟连续升高且 qB 正在占线时，会临时收紧 qB 实例的上下行总限速，涵盖手动加入的种子。延迟回落后逐步恢复原限速。关闭开关、qB 空闲或从网页停止服务时会尝试还原。如果连接中断，待恢复连接后再处理。如果强制杀进程，则在下次启动且 qB 可连通后还原。切换普通和备用限速时，PTFree 保留你原来的两套值。功能只调整已经连接的 qB 实例。

「总运行概览」显示物理卷已用、卷空闲和流量助手存储配额已用。该配额只用于流量助手同一时间持有的任务，不包含 Freeseed，任务清理后可以复用。PTFree 下载累计按最近24小时、7天、30天、365天及统计以来计算，时间轴显示北京时间。图上的 PPPoE 线来自路由器，PTFree 下载和上传合计 Freeseed 与流量助手已识别的 qB 种子流量，包括持续做种，同一任务只计一次，不包含普通手动添加的任务。采样覆盖率表示时段内有有效采样的时间比例。

旧版 Freeseed 目录投递缺少哈希时，名称、体积与导入时间均能唯一核对的任务可恢复归属。qB 两次采样之间的累计增量按时段平均显示。总览标出旧版本可能漏计的时段。
