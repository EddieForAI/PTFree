带宽调度

托管速率取「线路估值减去家庭预留与其他流量」和「托管总上限」两者中较低的值。

根据 qB 上传和 PPPoE 流量自动调整托管下载上限。每轮观察 90 秒，调整后留 15 秒让流量稳定。上传需求较低时使用可用下行额度。参考速率填写宽带实测值。填写家庭预留下行可给其他设备留出空间。

Freeseed 抢上传使用帮助

首次配置和试跑

  1. 在 M-Team「控制台 → 实验室 → 存取令牌」创建 API Access Token。在「PT配置 → M-Team」选择 API 地址、填入令牌并保存，再点「测试已保存的认证」。令牌框留空会保留旧令牌。
  2. 在「PT配置 → M-Team」设置扫描板块。在「Freeseed → 服务配置」选择 M-Team，设置保存方式和筛选条件，点击「保存 Freeseed 配置」。默认以文件投递方式运行，需填写运行 PTFree 的机器能访问的种子目录。
  3. 回到 Freeseed「运行概览」，点「测试读写」和「预览本页结果」。预览可以在暂停时执行，会查询列表与站点下载历史，并显示逐条筛选结果。
  4. 确认后，在「服务配置」取消「仅预览筛选结果」、保存，再在「运行概览」点「启动服务」。可点「立即扫描一次」触发一轮，或等待下次计划。

扫描和筛选

  • 扫描范围　每轮读取配置板块的第一页，至多 100 条。默认间隔 180 秒，最低 120 秒，可在其上叠加随机间隔。
  • 免费条件　默认只接受确认免费的种子，包括标准免费、双倍上传免费和有效的单种优惠。有限截止时间的免费种子须满足剩余时间，且优惠仍有效。明确标记免费的种子若没有截止时间，仍可通过此项。置顶本身不代表免费。正式申请前会复核详情；详情缺少部分活动信息时可用本轮列表结果补充。
  • 数值筛选　体积、做种人数、发布时间和免费剩余时间均可按字段勾选「不限」。勾选后对应数值停用，取消后填写正数，再保存。仍在有效期内的限时免费可跳过发布时间筛选，但仍受体积、人数、剩余时间和关键词等条件约束。
  • 关键词与 HR　每行一个普通关键词，忽略大小写。白名单填写后需至少命中一条，黑名单命中任意一条即排除。明确标记 HR、不可见或已封禁的种子会跳过。
  • 全站免费　在「PT配置」按站方公告录入开始和结束时间，时区为北京时间。正式复核时，活动期间非单种优惠的老种交由 流量助手 筛选，单种优惠继续走 Freeseed 规则。首页预览展示的是初筛结果。

保存种子文件与 qB 容量管理

  • 文件投递　托管容量为 0 时，PTFree 将种子保存为 MT-种子ID.torrent。qB 需要自行监控该目录才会接收。目录最低剩余空间可以勾选「不限」，系统仍需具备写权限和写入文件所需空间。
  • 托管容量　填写正数后，通过「全局配置」的 qB Web API 直接添加任务。再填写 qB 主机上的专用绝对目录，该目录需与流量助手的内容目录分开。「容量满时」可选择等待空间，或由 PTFree 从最旧且可确认归属的 Freeseed 托管任务开始回收任务和内容。回收依据是 PTFree 的托管记录，原有 qB 任务和文件投递任务不参与。
  • 测试读写　文件投递模式检查保存目录；启用托管容量时检查 qB 连接和托管配置。

去重、重试和状态

  • 下载历史　按状态筛选，查看种子 ID、保存时间或首次发现时间、尝试次数与原因。站点确认已下载或正在做种的种子会跳过。站点历史查询失败时暂缓申请。站点尚未记录的文件也会经过本地去重；写入中断可用持久化记录恢复。
  • 运行日志和重试　查看筛除、失败、等待配额等原因。网络失败会退避重试；单种达到最大次数后，可在「下载历史」手动重试。任务逐条发起，启动间隔至少 3 秒。认证异常时暂停自动请求，更新令牌或通过认证测试后恢复。
  • 配额和冷却　「运行概览」显示近 24 小时请求计数。开启本地请求配额后，队列达到程序上限会等待滚动窗口释放。站点限流也会触发冷却；页面显示来源、剩余时间和预计恢复时间。

服务控制、监控和备份

  • Freeseed「暂停服务」停止本模块的扫描。页面右上角「停止服务」关闭 PTFree 网页、看门狗及两个模块，需要从系统启动入口重新打开。Windows 包默认监听局域网，Linux 脚本默认监听本机；IPv4 选项只影响 PTFree 的站点请求。
  • 网络请求和操作进程有超时，网页长时间失去心跳时看门狗会尝试重启。/healthz 检查网页进程是否存活；/metrics 支持管理会话或数据目录 metrics.token 中的专用只读令牌。
  • 备份前停止整个服务，再复制数据目录。Windows 启动脚本使用 %LOCALAPPDATA%\MTFree，Linux 脚本默认使用 ~/.local/share/mtfree。配置、历史、数据库、认证文件和 secret.key 一起备份。管理密码可在「全局配置」底部修改。

流量助手使用帮助

首次配置

  1. 在「PT配置 → M-Team」保存 API 令牌并通过认证测试。按站方公告填写全站免费开始和结束时间（北京时间），两个模块共用这段时间。
  2. 开启 qBittorrent 的 Web UI。在「全局配置」填写其 Web API 地址和认证。使用 qB 5.2+ 可选 API 密钥，其余支持版本用用户名和密码；本模块最低支持 qB 4.3。「测试 qB 连接」读取表单当前值，测试后还需保存。qB 未启用 HTTPS 时填写 http://。
  3. 需要 PPPoE 采样时，在「全局配置」填写 RouterOS API-SSL、证书指纹及 PPPoE 接口名（例如 pppoe-CT），用具有 read,api 权限的账号。保存后测试。以前部署过旧版 MTFree 队列限制的实例可在该页撤销旧整形。
  4. 到「调度与容量」选择 M-Team，配置通用筛选、存储和带宽。在 流量助手「运行概览」点「启动后台下载」。可随时点「暂停后台下载」让托管任务停下来，并在概览查看等待原因。

选种、免费规则和并发

  • 开启「自动发现并加种」后，在「PT配置 → M-Team」选择综合区、成人区。综合区分类 ID 留空查全部，电影填 419，多个 ID 用逗号分隔。自动筛选支持做种人数下限、体积范围以及容量检查。
  • 启用的分区每次各取一页，每页最多 100 条。PTFree 合并、去重，并按做种人数排序。当前批次用完后按候选补页间隔取下一批；标准免费结束后查双倍上传免费，并记录本轮用过的种子 ID。
  • 后台主要接收已发布至少 24 小时、优惠有效且无明确 HR 标记的种子。免费新种和单种限时优惠交由 Freeseed。手动输入 ID 也要通过后台的免费和容量校验。加入 qB 前复核，运行中按免费复核间隔检查；已知优惠到期时先暂停依赖它的任务并复核。
  • 从一个下载位起步，约每 30 秒判断是否增加一个，同时遵守「最大同时下载数」。下载额度优先给 qB 已放行的任务。已有任务在 qB 排队时，PTFree 暂缓提交新任务。疑似慢种按有效下载样本和设定速率判定，暂停、排队、让道时间不计入。判定时长为 0 时关闭慢种清理。

种子管理和内容生命周期

  • 「新增种子」可按 M-Team 数字 ID 加入指定种子。关闭自动发现后仍可手动加入，已有托管任务继续由后台管理。「指定循环」或「设为循环」会在完成并清理后重新排队，每轮都要重新复核。
  • 所有 流量助手 托管种子统一使用 qB 标签 AutoSeeDonTouch。托管队列显示进度、上下行速度、状态与原因。「显示历史」显示结束的任务；可用「重新排队」再试。自动候选表给出体积、做种人数、免费到期时间和筛选结果。
  • 「暂停／恢复」针对单条任务。「移除」将任务从队列或 qB 中移除，保留已下载文件。「连文件删除」经确认移除 qB 任务及其内容。PTFree 在清理前会检查任务标识和路径归属。
  • 默认在下载完成后清理任务和内容。需要留存时，在「调度与容量」先填「保留并转移到」，再在对应任务上勾选「保留并转移」。完成后由 qB 将内容移入目标目录的独立子目录并接管。若与 Freeseed 重复，后台只会释放可确认是自己管理的任务。

存储和任务检查

  • 固态盘　设置 qB 主机的专用下载目录、流量助手存储配额和卷保留空间。配额按任务完整大小预留。远程 qB 使用默认下载目录下的直属子目录，且需在同一个卷上。
  • 内存盘　qB 与 PTFree 必须同机并通过回环地址连接。可填写已有内存盘，也可选择自动创建并设置大小和系统预留内存。「保存并创建或检查」可提前准备并显示路径。Windows 自动创建需要 ImDisk、AWEAlloc 及管理员权限；Linux 需要 tmpfs 挂载权限，启用交换空间时要求支持 noswap。内存盘在重启或卸载时丢失内容，未通过检查时后台会等待。
  • 任务状态检查　在「调度与容量」设置检查方式、运行时轮询间隔（15–35 秒），或点「立即检查」。本机 qB 可用「完成通知 + 定时检查」缩短完成后的等待；远程 qB 或已经使用其他完成程序时用「定时检查」。已启用全局临时下载目录的场景需要支持逐任务下载路径的 qB 5.1+。

带宽和延迟让路

  • 上传优先（自动）　在「调度与容量」选择模式并保存。PTFree 从 50 Mbps 或更低的下载上限起步，实测 qB 上传。观察到足够的上传流量后，以基线的 90% 为保护目标。每次用至少 90 秒的测速中位数判断，调整下载上限后等 15 秒再重新计时。确认掉速后降低托管下载并暂缓新增任务，观察上传是否回升。没有改善时结束本轮试探并重新学习，上传稳定后逐步加回下载速率。带宽调节期间任务保持连接，托管上传由 qB 控制。
  • 上传优先的参考值　参考下行和家庭预留下行用于计算下载预算，参考上行用于识别 PPPoE 是否接近饱和。托管下载总上限仍然有效。RouterOS 暂时无样本时，采用 qB 的实测流量。若 qB 手动设置了全局或备用限速，实际上传仍受该限速和对端需求影响。
  • 共享带宽　每个方向先从线路估值减掉家庭预留和观测到的其他流量，再套用托管总上限。勾选「不限」只取消该方向的固定上限，剩余带宽和让路条件仍然生效。已配置 RouterOS 却缺少当前采样，或可用额度过低时会暂停后台调度。
  • 线路估算　开启后，上下行各自采用近 7 天连续 5 分钟平均速率的峰值；缺少有效样本，或峰值低于对应参考值的 65% 时，使用参考值。关闭历史估算则使用填写的参考下行和上行。
  • 托管任务的延迟调度　使用「全局配置」的外网 Ping 地址和延迟升高阈值。在「调度与容量」设置采样间隔及持续升高时追加预留带宽或暂停后台下载。此项作用于 流量助手 托管任务。
  • qB 整体让路　在「全局配置」单独启用。延迟持续升高且 qB 正在传输时，临时收紧整个 qB 实例的上下行总限速，手工添加的种子也会受影响。延迟恢复后逐步还原。关闭该功能、停止服务或连接恢复时会处理待还原的限速，可在该页查看状态。
